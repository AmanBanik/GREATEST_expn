# Prepare the Medium Article (Do Not Draft Too Early)

1. Read the session logs, experiment records, source, analysis notes, and evidence map.
2. Build a chronology of what the user actually did, what they expected, what happened, and what changed next.
3. Ask for missing first-person details rather than inventing them.
4. Create an outline first. Suggested flow: curiosity/question → experimental setup → first surprising observation → inspecting compiler output → controlled comparisons → what the evidence supports → what remains unknown → reflection.
5. Make an evidence map for every numeric statement, hardware claim, code excerpt, and chart.
6. Keep the distinction between dependent-chain latency and multi-chain throughput explicit. Do not compare unlike operation counts as a controlled test.
7. Explain that source-level/nominal bytes are not automatically measured DRAM traffic.
8. Clearly state that WSL2 lacked hardware PMU counters if that limitation remains true at the time of writing.
9. Draft in first person only from recorded experience. No fabricated quotes, outcomes, exact cache latencies, or dramatic failures.
10. Ask the user to review the outline and evidence map before producing a polished full draft.
