# Future Medium Article Style and Evidence Contract

The eventual article should use first-person perspective and a curious, experience-led narrative. Explain systems concepts in plain language without stripping out technical precision. Let real experiments, surprises, debugging, and limitations drive the story; avoid generic textbook openings and exaggerated claims.

## Writing requirements
- Use the author's actual experience and first-person voice; do not invent thoughts, dialogue, failures, motives, or results.
- Use a curiosity-driven hook only when the evidence/story supports it.
- Explain jargon when it first becomes necessary.
- Use readable paragraphs, occasional bullets, and code snippets only where they help the reader reproduce or understand the experiment.
- Be candid about WSL2 limitations, missing PMU counters, noisy measurements, and uncertain attribution.
- Distinguish measured results from explanatory models.
- Avoid claiming exact L1/L2/L3/DRAM latency from one timing sweep unless independently validated.
- End with a genuine lesson, unresolved question, or invitation to discuss—not a forced motivational slogan.

## Before drafting
Create an evidence map connecting every numeric claim, chart, and hardware claim to raw files or source lines. Flag claims without evidence. Ask the user for missing personal context instead of making it up.
